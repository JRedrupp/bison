# Mojo Toolchain Revival Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get bison building and testing clean against the latest Mojo nightly by forking and fixing the vendored `marrow` submodule, fixing bison's own mechanical breaks, and fixing the nightly-CI drift detector so this doesn't happen again.

**Architecture:** Three independent, sequential PRs. PR 1 fixes `marrow` in a personal fork and repoints bison's submodule at it (bison's own `pixi.toml` pin is untouched). PR 2 bumps bison's `pixi.toml` pin to latest nightly and fixes the resulting bison-side compile errors. PR 3 fixes the nightly workflow's dead version-pin substitution and adds a failure-tracking-issue step.

**Tech Stack:** Mojo (`def`-only, nightly), Pixi, `vendor/marrow` (Apache-2.0 Arrow-in-Mojo library, git submodule), GitHub Actions, `gh` CLI.

## Global Constraints

- Zero-warnings policy: `pixi run check` (`mojo package bison/ --Werror`) must have zero warnings and zero errors before any bison-side PR is opened.
- Use `def` for every function/method — `fn` is deprecated on nightly. This applies to both bison and marrow source.
- Any method that mutates struct fields must declare `mut self` explicitly, or the mutation is silently lost (copy-on-call).
- Never commit directly to `main` — always work on a feature branch (per project convention).
- `bison/_version.mojo` is generated by `scripts/gen_version.py` — never hand-edit it.
- Per bison's `CLAUDE.md` session-notes rule: create `SESSION.md` at the repo root if it doesn't exist, and append an entry immediately (not batched at the end) for every tech-debt/refactoring observation noticed while working, including incidental ones. `SESSION.md` is gitignored — never commit it.
- marrow-side work (PR 1) additionally follows `vendor/marrow/CLAUDE.md`: `def` not `fn`; `comptime` not `alias`; never call another type's `_underscore`-prefixed methods from outside it; `unsafe_ptr()` may only be called from `buffers.mojo`, `views.mojo`, `c_data.mojo`; avoid `AnyOrigin`/`unsafe_origin_cast` — use parametric origins; conventional-commit messages (`fix:`, `chore:`, etc.); add a `CHANGELOG.md` entry under `## [Unreleased]` for every meaningful change.
- A local, current checkout of the Mojo/MAX compiler source lives at `/home/jake/Development/modular`, with `origin/main` fetched and matching today's target nightly (`1.0.0b3.dev2026080206` / `26.5.0.dev2026080206`) exactly. Use `git show origin/main:<path>` or `git grep <term> origin/main -- <path>` there instead of guessing at a new API's shape — it is the ground truth for what changed. Re-fetch (`git fetch origin`) if the target nightly has moved on since this plan was written.

        uses: actions/github-script@v7

            const runUrl = `${context.serverUrl}/${context.repo.owner}/${context.repo.repo}/actions/runs/${context.runId}`;

              owner: context.repo.owner,

              labels: label,
            });
            if (issues.length > 0) {

                repo: context.repo.repo,

                repo: context.repo.repo,

            }
